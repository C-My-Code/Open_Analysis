# WP-000B: minimal interpretations of ambiguous spec points

1. **Stackup "validators" live in `validate_board`.** board-model.md 6.2 lists z-contiguity, id sequence and material resolution as `Stackup` validators, while section 13 lists `MODEL.STACKUP_Z` and `MODEL.DANGLING_REF` as `validate_board` checks. A pydantic validator would make those codes untestable and would block `model_construct` readers. They are implemented in `validate_board` only (material kind mismatch reports `MODEL.DANGLING_REF`). `ArcSeg` keeps its radius check as a real validator (1e-9 m).
2. **`schema` field name.** Contracts name a field `schema`, which shadows `BaseModel.schema()`. Kept as specified. pydantic's UserWarning is filtered narrowly in `oa_model._base`. mypy needs a `# type: ignore[assignment]` on those lines.
3. **`parse_quantity` dimensions.** Added `"angle"` (rad, deg) so `60deg` works for `Etch.value`; `Etch` picks angle or length from its `kind`. `oz` is rejected for every dimension (it is not a length). Quantity strings are accepted by field types (`Length`, `Frequency`, ...), not only by loaders.
4. **`CrossSection.key()` canonicalizes first** (so it is translation invariant even for non-canonical input). The canonical shift is snapped to the 1 nm grid so that sub-nm jitter of one coordinate cannot move the whole section across a rounding boundary. Consequence: the canonical u=0 is the signal-bbox midpoint to within 0.5 nm. Lengths are rounded to integer nm, material parameters (everything under `model`, `conductivity`, `dk_z_over_dk_xy`, `background_dk`, Huray ratios) to 6 significant digits. `symmetric_about_u0` is checked in `canonicalize` (conductors only, 1 nm tolerance), not in a model validator.
5. **`Structure3D.key()` / `EMProblem.key()`** prefixes are `st1:` / `em1:` (the spec gives no prefix). `EMProblem.key()` combines the structure key with an exact (non-rounded) canonical encoding of the remaining fields, minus `name`.
6. **`apply_physics` semantics.** Order: sidecar materials, aliases, defaults, layer overrides in order, z recompute, Dk/Df upgrade, via plating. Selector criteria are OR-ed with fnmatch globs; an empty selector is a validation error. `defaults.conductor_material` applies only to conductor layers whose current material has source `ingest` or `default`. `defaults.roughness` fills only `NoRoughness` surfaces. The result's `stackup.materials` lists only materials referenced by layers (first appearance order); lookups go sidecar, then board, then library. `PhysicsOverlay.temperature` is carried by the overlay for consumers and is not written into the `Board`. An override matching no layer logs a warning (no channel to return diagnostics from a function that returns `Board`).
7. **Newer-minor pruning** is model-driven (drop the fields pydantic reports as `extra_forbidden`, retry) instead of walking `schemas/board-model.v1.json`. The result is identical for additive changes and also handles discriminated unions. It emits `MODEL.NEWER_MINOR` as a `warnings.warn(OAModelWarning)` and log record; `board_from_dict` returns the `Diagnostic`.
8. **`.oab` packing threshold** is 64 elements per array (the spec says "automatically above 5 MB of array data"; `dump_board` chooses the container from the file suffix and packs larger arrays).
9. **`schemas/oa-result.v1.json` is not produced here.** It belongs to `oa_results`, which `oa_model` (L0) cannot import. `python -m oa_model.schemas` writes the other seven files (`oa-project.v1.json` is an extra). The integrator should add a generator call for `oa-result` once `oa_results` exists.
10. **Library material values** in `data/materials.yaml` are recalled datasheet values; entries say "verify" in their citation where applicable.
